## 二、已实现策略详解

### 策略一：标题层级感知切片

**解决的问题**：切出来的 chunk 是孤立的正文片段，检索命中后不知道它属于哪个章节，LLM 无法准确引用来源。

**实现位置**：`src/data_loader.py` + `src/document_splitter.py` + `src/rag_pipeline.py`

**数据流**：

```
PDF 加载
  └─ _extract_outline()        # 递归遍历书签树，提取 {title, page, level}
  └─ _build_page_to_section()  # 按页码区间建立 0-based page → title 映射
  └─ metadata['_page_to_section'] = {0: "第1章", 5: "第2章", ...}
       ↓
切分器 split()
  └─ page_to_section = document.metadata.get('_page_to_section', {})
  └─ section_path = page_to_section.get(current_page - 1, '')
  └─ chunk.metadata['section_path'] = section_path
       ↓
上下文构建 _build_context_with_budget()
  └─ section_path = chunk.metadata.get('section_path', '')
  └─ text = f"[{section_path}]\n{text}"   # 前置章节名
```

**关键设计细节**：

1. `_page_to_section` 用 `_` 前缀命名，表示内部传递字段，不直接存入 chunk metadata
2. `base_metadata` 过滤掉嵌套 dict，只保留 `str/int/float/bool` 类型，避免 ChromaDB 入库报错
3. 页码转换：`[PAGE:N]` 标记是 1-based，映射表 key 是 0-based，查表时用 `current_page - 1`
4. 无 Outline 的 PDF 降级处理：`page_to_section` 为空 dict，`section_path` 为空字符串，行为与改动前一致

**效果**：LLM 看到的上下文从孤立正文变为带章节归属的内容：

```
改动前：
[[1]] 函数定义定义一个用户自定义的函数对象...

改动后：
[[1]] [7. 复合语句]
函数定义定义一个用户自定义的函数对象...
```

API 返回的 sources 也带上 `section_path`，引用溯源精确到章节：

```
[[1]] python-doc-27-34.pdf | 7. 复合语句 · 第224页 | 相关度 0.700
```

### 策略二：碎片块合并（简化版 Section ID 合并）

**解决的问题**：递归切分后会产生长度极短的碎片 chunk（如单行标题、孤立标点），这类 chunk 语义不完整，进入向量库后会干扰检索。

**与 RAGFlow 的差异**：RAGFlow 的 Section ID 合并基于完整的标题层级树，同节内容强制合并到 1024 token。当前项目简化为：长度小于 `min_chunk_size` 的碎片块无条件合并到前一块。

**实现位置**：`src/document_splitter.py` → `_merge_small_chunks()`

```python
def _merge_small_chunks(self, chunks: List[TextChunk]) -> List[TextChunk]:
    if not chunks:
        return chunks
    merged = [chunks[0]]
    for chunk in chunks[1:]:
        if len(chunk.content) < self.min_chunk_size and merged:
            prev = merged[-1]
            merged[-1] = TextChunk(
                content=prev.content + "\n" + chunk.content,
                metadata={**prev.metadata, "chunk_size": len(prev.content) + len(chunk.content) + 1},
                chunk_id=prev.chunk_id,
                start_idx=prev.start_idx,
                end_idx=chunk.end_idx,
            )
        else:
            merged.append(chunk)
    return merged
```

**参数**：`min_chunk_size=50`（默认），可在初始化时调整。

### 策略三：Overlap 滑动窗口

**解决的问题**：相邻 chunk 边界处语义断裂，检索时边界附近的内容可能被切断。

**实现位置**：`RecursiveCharacterSplitter.__init__()` 的 `chunk_overlap` 参数，`settings.yaml` 中配置 `default_chunk_overlap: 30`。

这是原有功能，无需改动。

### 策略五：目录页过滤

**解决的问题**：PDF 目录页的条目与正文内容高度相似（都包含章节标题），如果被索引进向量库，会严重干扰检索——用户问"第3章讲什么"，目录条目和正文都会被召回，但目录条目没有实质内容。

**实现位置**：`src/data_loader.py` → `_detect_toc_pages()`

```python
def _detect_toc_pages(self, reader, total_pages: int) -> set:
    toc_pages = set()
    scan_limit = max(1, int(total_pages * 0.2))  # 只扫描前 20%，避免误伤正文

    for i in range(min(scan_limit, total_pages)):
        text = (reader.pages[i].extract_text() or "").strip()
        first_line = text.split('\n')[0].strip() if text else ""
        normalized = re.sub(r'[\s\u3000]+', '', first_line)
        if self._TOC_PATTERN.match(normalized):
            toc_pages.add(i)
            # 把后续目录条目页也过滤（最多连续 10 页）
            for j in range(i + 1, min(i + 11, total_pages)):
                next_text = reader.pages[j].extract_text() or ""
                if re.search(r'\.{3,}|\s\d{1,4}\s*$', next_text, re.MULTILINE):
                    toc_pages.add(j)
                else:
                    break
            break
    return toc_pages
```

**识别逻辑**：
- 目录页首行匹配关键词：`目录 / 目次 / Contents / Table of Contents / 致谢`
- 后续页面含大量省略号（`...`）或行尾为纯数字（页码），判定为目录条目页，一并过滤
- 只扫描前 20% 的页面，避免误伤正文中偶尔出现的"目录"字样

## 三、未实现策略说明

### 策略四：表格与图片上下文附加

**未实现原因**：`pypdf` 的文本提取是纯文本流，无法识别表格结构（行列关系丢失）。要实现真正的表格解析，需要引入 `pdfplumber` 或 `camelot` 等专用库，或使用 MinerU / Docling 等视觉模型后端。

**当前影响**：PDF 中的表格内容会被当作普通文本处理，行列结构丢失，但文字内容仍会被索引。

**后续扩展方向**：在 `_load_pdf()` 中用 `pdfplumber` 提取表格，转换为 Markdown 格式后与正文合并。

### 策略六：层级树合并

**未实现原因**：需要先构建完整的标题层级树（章 → 节 → 条款），再按 `depth` 参数决定切片粒度。当前 PDF 文本提取后标题识别依赖书签，无书签时无法可靠地构建层级树。

**后续扩展方向**：结合策略一的 Outline 提取结果，对有完整书签的 PDF 实现层级树合并。

## 五、重新索引

以上改动在索引阶段生效，需要重新索引才能让向量库中的 chunk 携带 `section_path` 和目录过滤效果：

```bash
python main.py index --source data/raw/
```

ChromaDB 的 `add()` 使用 upsert 语义，相同 chunk_id 会覆盖旧数据，无需手动清库。
