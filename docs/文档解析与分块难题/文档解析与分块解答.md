# 文档解析与分块解答

**面试题**：文档解析与分块（Parsing & Chunking）

1. 面对包含大量行业术语的技术手册，你会采用什么策略进行文本提取和切片？
2. 如何尽可能保留文档的上下文语义连贯性？

---

## 问题一：文本提取与切片策略

技术手册类文档有三个特殊性，决定了不能用通用的固定 token 数盲切：

- **术语密度高**：缩写、专有名词、型号编号，脱离上下文就失去意义
- **层级结构深**：章 → 节 → 条款 → 子条款，切片后丢失归属关系
- **目录干扰**：目录页条目与正文高度相似，会严重干扰向量检索

针对这三个问题，本项目采用以下策略：

---

### 1.1 文本提取：中文 PDF 专项清洗

使用 `pypdf` 提取每页文本，针对中文 PDF 常见的乱码和断行问题做专项清洗：

```python
def _clean_pdf_text(self, text: str) -> str:
    # 单个换行（断词）→ 空格，保留双换行（段落分隔）
    text = re.sub(r'(?<!\n)\n(?!\n)', ' ', text)
    # 去除多余空格和制表符
    text = re.sub(r'[ \t]+', ' ', text)
    # 关键：去除中文字符之间的空格（PDF 提取常见问题）
    text = re.sub(r'(?<=[\u4e00-\u9fff])\s+(?=[\u4e00-\u9fff])', '', text)
    # 去除中文和标点之间的空格
    text = re.sub(r'(?<=[\u4e00-\u9fff])\s+(?=[，。！？、；：""''（）【】])', '', text)
    return text.strip()
```

每页文本插入 `[PAGE:N]` 标记，切分后 chunk 可反查原始页码，实现精准溯源。

---

### 1.2 目录页过滤

目录页的条目与正文内容高度相似（都包含章节标题），如果被索引进向量库，会严重干扰检索——用户问"第3章讲什么"，目录条目和正文都会被召回，但目录条目没有实质内容。

**实现**：扫描前 20% 页面，识别含"目录/Contents"关键词的页面及其后续目录条目页，索引时跳过：

```python
def _detect_toc_pages(self, reader, total_pages: int) -> set:
    toc_pages = set()
    scan_limit = max(1, int(total_pages * 0.2))  # 只扫描前 20%，避免误伤正文

    for i in range(min(scan_limit, total_pages)):
        first_line = (reader.pages[i].extract_text() or "").split('\n')[0].strip()
        normalized = re.sub(r'[\s\u3000]+', '', first_line)
        if self._TOC_PATTERN.match(normalized):  # 匹配"目录/Contents"等关键词
            toc_pages.add(i)
            # 后续含省略号或行尾数字的页面也过滤（目录条目特征）
            for j in range(i + 1, min(i + 11, total_pages)):
                next_text = reader.pages[j].extract_text() or ""
                if re.search(r'\.{3,}|\s\d{1,4}\s*$', next_text, re.MULTILINE):
                    toc_pages.add(j)
                else:
                    break
    return toc_pages
```

### 1.3 切片策略：递归字符切分

对于行业术语密集的文档，选择**递归字符切分**（RecursiveCharacterSplitter），按语义边界优先级切分：

```
段落（\n\n）→ 行（\n）→ 句子（ ". " ）→ 单词/（空格）→ 字符
```

相比固定 token 数盲切，递归切分优先在自然语义边界处断开，减少术语被切断的概率。

关键参数：

| 参数 | 值 | 说明 |
|------|-----|------|
| `chunk_size` | 256 | 较小粒度，每个 chunk 语义更聚焦，embedding 向量更精准 |
| `chunk_overlap` | 30 | 相邻 chunk 重叠，保留边界处语义连贯性 |
| `min_chunk_size` | 50 | 碎片块合并阈值 |

**为什么选 256 而不是 512**：医疗技术文档中每个知识点相对独立，较小的 chunk 能让 embedding 向量更精准地表达单一语义，避免多个不相关知识点混入同一向量，提升检索精度。

---

### 1.4 碎片块合并

递归切分后会产生长度极短的碎片 chunk（如单行标题、孤立标点），这类 chunk 语义不完整，进入向量库后会干扰检索。

**实现**：切分后对长度小于 `min_chunk_size=50` 的碎片块合并到前一块：

```python
def _merge_small_chunks(self, chunks: List[TextChunk]) -> List[TextChunk]:
    merged = [chunks[0]]
    for chunk in chunks[1:]:
        if len(chunk.content) < self.min_chunk_size and merged:
            prev = merged[-1]
            # 合并到上一块，继承上一块的 chunk_id 和 section_path
            merged[-1] = TextChunk(
                content=prev.content + "\n" + chunk.content,
                metadata={**prev.metadata, "chunk_size": len(prev.content) + len(chunk.content) + 1},
                chunk_id=prev.chunk_id,
                start_idx=prev.start_idx,
                end_idx=chunk.end_idx,
            )
        else:
            merged.append(chunk)
    return merged
```

## 问题二：保留上下文语义连贯性

本项目通过三个机制保留语义连贯性，分别解决不同层面的问题：

---

### 2.1 标题层级感知切片——解决"归属丢失"问题

**问题**：切出来的 chunk 是孤立的正文片段，检索命中后不知道它属于哪个章节，LLM 无法准确理解内容的语义归属。

**方案**：提取 PDF 书签目录，建立页码 → 章节标题映射，每个 chunk 携带 `section_path` 字段：

```python
# data_loader.py：提取书签，建立页码映射
def _extract_outline(self, reader) -> List[Dict]:
    entries = []
    def _walk(items, level=1):
        for item in items:
            if isinstance(item, list):
                _walk(item, level + 1)
            else:
                page_num = reader.get_destination_page_number(item)
                entries.append({'title': item.title.strip(), 'page': page_num, 'level': level})
    _walk(reader.outline)
    return sorted(entries, key=lambda x: x['page'])

def _build_page_to_section(self, entries, total_pages) -> Dict[int, str]:
    # 按页码区间建立映射：第5-11页 → "第3章 安装与配置"
    mapping = {}
    for i, entry in enumerate(entries):
        end = entries[i + 1]['page'] if i + 1 < len(entries) else total_pages
        for p in range(entry['page'], end):
            mapping[p] = entry['title']
    return mapping
```

```python
# document_splitter.py：切分时注入 section_path
section_path = page_to_section.get(current_page - 1, '')
metadata = {**base_metadata, "page": current_page, "section_path": section_path, ...}
```

```python
# rag_pipeline.py：上下文构建时前置章节名
header = ' | '.join(filter(None, [filename, section_path]))
if header:
    text = f"[{header}]\n{text}"
```

**效果**：LLM 看到的上下文从孤立正文变为带归属信息的内容：

```
改动前：
[[1]] 函数定义定义一个用户自定义的函数对象...

改动后：
[[1]] [python-doc-27-34.pdf | 7. 复合语句]
函数定义定义一个用户自定义的函数对象...
```

来源显示也精确到章节：

```
[[1]] python-doc-27-34.pdf | 7. 复合语句 · 第224页 | 相关度 0.878
```

**降级处理**：无书签的 PDF，`section_path` 为空字符串，行为与改动前一致，不影响正常使用。

---

### 2.2 Overlap 滑动窗口——解决"边界断裂"问题

**问题**：相邻 chunk 之间的边界处语义会断裂，一句话可能被切分到两个 chunk，导致两个 chunk 都不完整。

**方案**：相邻 chunk 之间保留 `chunk_overlap=30` 字符的重叠，确保边界处的语义连续：

```python
# 字符级切分时的重叠实现
for i in range(0, len(text), self.chunk_size - self.chunk_overlap):
    chunks.append(text[i:i + self.chunk_size])
```

例如一句话"函数调用时，实际参数会被引入被调函数的局部符号表"被切分到两个 chunk 时，两个 chunk 都包含这句话的部分内容，检索时任意一个 chunk 被命中都能获取到完整语义。

---

### 2.3 碎片块合并——解决"语义碎片"问题

**问题**：切分后产生的极短 chunk（如单行标题"3.1 主泵规格"、孤立的单位"bar"）语义不完整，进入向量库后会被错误召回。

**方案**：长度小于 50 字符的碎片块合并到前一块，保证每个 chunk 都有足够的语义信息：

```
切分前：
  chunk A: "主泵规格"（4字符，碎片）
  chunk B: "额定压力：350bar，流量：120L/min"

合并后：
  chunk A+B: "主泵规格\n额定压力：350bar，流量：120L/min"
```

合并后的 chunk 既包含了标题（提供上下文），又包含了具体参数（提供内容），语义更完整。

## 总结

| 问题 | 策略 | 实现位置 |
|------|------|----------|
| 中文 PDF 乱码/断行 | 专项文本清洗 | `data_loader._clean_pdf_text()` |
| 目录页干扰检索 | 目录页过滤（策略五） | `data_loader._detect_toc_pages()` |
| 术语被切断 | 递归字符切分（语义边界优先） | `document_splitter.RecursiveCharacterSplitter` |
| 碎片 chunk 干扰 | 碎片块合并（策略二） | `document_splitter._merge_small_chunks()` |
| 边界处语义断裂 | Overlap 滑动窗口（策略三） | `chunk_overlap=30` 参数 |
| chunk 归属丢失 | 标题层级感知（策略一） | `data_loader._extract_outline()` + `document_splitter.split()` |

**未实现的方向**（后续可扩展）：
- 表格解析：pypdf 无法识别表格结构，需引入 `pdfplumber` 或视觉模型后端
- 无书签 PDF 的正则标题识别：参考 RAGFlow 的 `title_frequency()` 通过统计编号模式自动识别标题
