助手：作用域是Python中决定变量可见性和生命周期的关键概念。根据参考文档，作用域指的是程序执行过程中可以直接访问的命名空间层次结构 [[1]] [[4]]。

在Python程序执行时，至少存在三个嵌套的作用域层次：
1. **最内层局部作用域**：首先被搜索，包含局部变量 [[1]] [[4]]
2. **中间层作用域**：包含所有调用函数中的非局部但非全局的命名，从最内层调用函数开始搜索 [[1]] [[4]]
3. **模块全局作用域**：包含当前模块的全局命名 [[1]] [[4]]
4. **最外层内置作用域**：最后搜索，包含内置命名 [[1]] [[4]]

作用域的一个重要特性是：**作用域是由代码静态确定的**。函数的全局作用域是函数定义所在模块的命名空间，与函数被调用的位置或别名无关 [[2]] [[3]]。然而，命名的实际搜索过程是动态的，在运行时确定 [[2]] [[3]]。

Python的一个特别规则是：如果没有使用`global`语句，赋值操作总是在最内层作用域进行 [[2]] [[3]]。如果变量被声明为`global`，那么所有对该变量的引用和赋值都会直接搜索包含该模块全局命名的作用域 [[1]] [[4]]。

文档中还提供了作用域和命名空间的示例代码，展示了`global`和`nonlocal`如何影响变量绑定 [[5]]。

类的定义在Python中是一个可执行语句，用于创建类对象 [[3]]。其语法以关键字 `class` 开头，后跟类名和可选的继承列表 [[3]]。

类定义与函数定义（`def` 语句）类似，需要先执行才能生效 [[1]] [[2]]。执行类定义时，会创建一个新的命名空间作为局部作用域 [[1]] [[2]] [[5]]。在这个局部作用域（即类体）中，通常包含函数定义（即方法），但也可以包含其他语句 [[1]] [[2]]。在该作用域内进行的赋值操作（包括函数定义）会成为这个新命名空间的局部变量 [[5]]。

当类定义正常执行完毕后，会基于这个新创建的命名空间生成一个类对象 [[5]]。原始的局部作用域（类定义之前生效的那个）会得到恢复，并且这个类对象会绑定到类定义头部指定的类名上 [[5]]。

需要注意的是，在类定义域（类体）中定义的名称，在类的方法内部并不可见 [[4]]。此外，类定义中函数（方法）的参数列表通常具有特殊形式，这由方法调用的协议决定 [[1]] [[2]]。

异常是一种打断代码块正常控制流程以处理错误或其它意外情况的方法 [[1]]。在Python中，异常在错误被检测到的点引发，并可以通过包围它的代码块或直接、间接调用发生错误的代码块的代码块来处理 [[1]]。

Python解释器在检测到运行时错误（例如除零）时会自动引发一个异常 [[1]]。此外，程序员也可以通过 `raise` 语句显式地引发异常 [[1]]。异 常处理器通过 `try` 语句来定义 [[1]]。

异常有不同的类型，其类型名称会作为错误消息的一部分打印出来 [[5]]。对于所有内置异常，打印出的异常类型字符串就是内置异常的名称 [[5]]。标准异常的名称是内置的标识符，而不是保留的关键字 [[3]] [[4]]。

用户代码可以引发内置异常，例如用于测试异常处理程序或报告错误情况 [[2]]。程序员也可以从 `Exception` 类或其子类派生新的异常来定义用 户自定义的异常 [[2]]。

异常通过 `try` 语句定义的异常处理器来处理 [[1]]。处理机制遵循以下流程：

1. **异常引发**：当检测到运行时错误（如除零）时，Python解释器会自动引发一个异常 [[1]]。程序员也可以通过 `raise` 语句显式地引发异常 [[1]]。

2. **异常捕获与处理**：`try` 语句的 `except` 子句用于指定捕获和处理特定异常 [[3]]。异常处理器不仅能处理直接发生在 `try` 子句中的异常，还能处理在 `try` 子句中调用的函数（甚至间接调用的函数）所引发的异常 [[4]]。

3. **清理操作**：`try` 语句的 `finally` 子句用于指定清理代码，无论前面的代码是否出现异常，它都会执行 [[3]]。

4. **处理模型**：Python使用“终止”模型进行异常处理。这意味着异常处理器可以查明发生了什么并在外层继续执行，但它不能修复错误的根源并 重试失败的操作（除非通过从顶层重新进入出错的代码片段）[[3]]。

5. **未处理异常**：如果一个异常没有被任何处理器捕获，解释器会终止程序的执行或返回到其交互式主循环。在这两种情况下，除非异常是 `SystemExit`，否则解释器都会打印出一个栈回溯 [[3]]。

6. **异常标识**：异常通过类的实例来标识 [[3]]。用户代码可以引发内置异常，也可以从 `Exception` 类或其子类派生来定义新的异常 [[2]]。

以下为基于文档片段的推断：异常处理的核心是使用 `try...except...finally` 结构来捕获、处理和清理异常，确保程序在遇到错误时能够以可控的方式响应或终止。
