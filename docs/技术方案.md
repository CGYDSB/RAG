# 垂直领域复杂文档 RAG 系统技术方案

**项目**：医疗领域内部技术文档智能问答系统
**技术栈**：Python / FastAPI / ChromaDB / BGE / DeepSeek / jieba

---

## 一、系统架构概览

```
用户问题
   ↓
[多轮消歧] 含指代词时 LLM 改写为完整问题
   ↓
Embedding（bge-small-zh-v1.5）→ 查询向量化
   ↓
混合检索
  ├─ 向量检索（ChromaDB 余弦相似度 KNN）→ Top-10 候选
  └─ 关键词检索（jieba 分词 + BM25 倒排索引）→ Top-10 候选
         ↓
    归一化加权融合（0.7 × vector_score + 0.3 × keyword_score）
   ↓
相似度阈值过滤（final_score ≥ 0.3）
   ↓
无关问题检测（vector_score < 0.3 → 直接拒答，不调用 LLM）
   ↓
父子 chunk：命中子块 → 取父块内容（上下文更完整）
   ↓
Token 预算控制 → 构造上下文（tiktoken 精确计数，整体跳过低相关 chunk）
   ↓
对话历史压缩注入（最近 2 轮完整保留，更早轮次 LLM 增量压缩成摘要）
   ↓
Prompt 构造（防幻觉 9 条规则 + 章节归属前缀）
   ↓
LLM 生成（DeepSeek）→ 带 [[序号]] 引用的回答
   ↓
引用验证（过滤超出范围的引用序号）
   ↓
返回答案 + 来源文件 + 章节 + 页码
```

## 二、必做部分一：文档解析与分块

### 2.1 文本提取策略

支持 PDF / TXT / MD / DOCX / HTML 五种格式，核心在 PDF 处理上做了专项优化。

**PDF 文本清洗流程**（针对中文 PDF 提取乱码问题）：

```python
def _clean_pdf_text(self, text: str) -> str:
    # 1. 单个换行（断词）→ 空格，保留双换行（段落）
    text = re.sub(r'(?<!\n)\n(?!\n)', ' ', text)
    # 2. 去除多余空格和制表符
    text = re.sub(r'[ \t]+', ' ', text)
    # 3. 关键：去除中文字符之间的空格（PDF提取常见问题）
    text = re.sub(r'(?<=[\u4e00-\u9fff])\s+(?=[\u4e00-\u9fff])', '', text)
    # 4. 去除中文和标点之间的空格
    text = re.sub(r'(?<=[\u4e00-\u9fff])\s+(?=[，。！？、；：""''（）【】])', '', text)
    return text.strip()
```

### 2.2 分块策略

采用**递归字符切分**（RecursiveCharacterSplitter），按语义边界优先级切分：

```
段落（\n\n）→ 行（\n）→ 中文句子（。！？；）→ 英文句子（. ）→ 单词（空格）→ 字符
```

关键参数配置：

| 参数 | 值 | 说明 |
|------|-----|------|
| chunk_size | 256 | 较小粒度，语义更聚焦（子块） |
| chunk_overlap | 30 | 重叠保留上下文连贯性（策略三） |
| min_chunk_size | 50 | 碎片块合并阈值（策略二） |

**策略二：碎片块合并**

切分后对长度小于 `min_chunk_size=50` 的碎片块合并到前一块：

```python
def _merge_small_chunks(self, chunks) -> List[TextChunk]:
    merged = [chunks[0]]
    for chunk in chunks[1:]:
        if len(chunk.content) < self.min_chunk_size and merged:
            prev = merged[-1]
            merged[-1] = TextChunk(content=prev.content + "\n" + chunk.content, ...)
        else:
            merged.append(chunk)
    return merged
```

## 三、必做部分二：基础召回架构（混合检索）

### 3.1 整体流程

```
Query
  ├─→ Embedding（bge-small-zh-v1.5）→ 向量检索（ChromaDB）→ Top-10 候选
  └─→ jieba 分词 + BM25 倒排索引 → Top-10 候选
         ↓
    归一化后加权融合（0.7 × vector + 0.3 × keyword）
         ↓
    相似度阈值过滤（final_score ≥ 0.3）
         ↓
    无关问题检测（vector_score < 0.3 → 直接拒答）
         ↓
    Top-5 最终结果
```

### 3.2 向量检索

使用 `BAAI/bge-small-zh-v1.5` 作为 Embedding 模型，专为中文语义理解优化，本地运行，dim=512。

向量检索基于余弦相似度（KNN）：

$$\text{cosine\_sim}(q, d) = \frac{q \cdot d}{\|q\| \cdot \|d\|}$$

BGE 模型做了 L2 归一化，向量长度为 1，余弦相似度等价于点积。ChromaDB 返回余弦距离，代码转换：`score = 1 - distance`。

bge 模型检索时加前缀提升召回精度（索引时不加）：

```python
self._query_prefix = "为这个句子生成表示以用于检索相关文章："
```

### 3.3 关键词检索（jieba + BM25）

引入 jieba 分词，解决原有空格切分对中文无效的问题：

```python
def _tokenize(self, text: str) -> List[str]:
    import jieba.posseg as pseg
    tokens = []
    for word, flag in pseg.cut(text):
        if word in self._CN_STOPWORDS or len(word) < 2:
            continue
        tokens.append(word)
        # 名词（n开头）权重翻倍：重复加入一次
        if flag.startswith('n') and len(word) >= 2:
            tokens.append(word)
    return tokens
```

**BM25 评分**（默认，可切换 TF-IDF）：

$$\text{score}(t, d) = \text{IDF}(t) \times \frac{\text{TF}(t,d) \cdot (k_1 + 1)}{\text{TF}(t,d) + k_1 \cdot \left(1 - b + b \cdot \dfrac{|d|}{\text{avgdl}}\right)}$$

$$\text{IDF}(t) = \ln\left(\frac{N - df(t) + 0.5}{df(t) + 0.5} + 1\right)$$

其中 $k_1 = 1.5$（TF 饱和系数），$b = 0.75$（文档长度归一化系数）。相比 TF-IDF，BM25 加入 TF 饱和（词频越高增益递减）和文档长度归一化（长文档里词频高不额外奖励）。

**关键词索引持久化**：索引完成后自动构建并持久化到 `data/keyword_index.pkl`，BM25 额外记录文档长度信息，启动时自动加载。

评分方式切换（`settings.yaml`）：

```yaml
retrieval:
  hybrid_search:
    keyword_method: "bm25"    # 或 "tfidf"
```

### 3.4 融合策略

两路结果各自归一化后加权融合：

$$\text{final\_score} = \alpha \cdot \frac{s_v}{s_v^{\max}} + (1-\alpha) \cdot \frac{s_k}{s_k^{\max}}$$

其中 $\alpha = 0.7$（向量权重），归一化消除量纲差异（向量相似度 $[0,1]$，BM25 分数无上界）。

**权重设计逻辑**：
- 向量检索权重更高（0.7），语义理解是主要需求
- 关键词权重（0.3）保证专有名词、型号等精确词不被遗漏
- 两路都命中的 chunk 得分叠加，天然实现"语义+精确"双重过滤

### 3.5 空结果降级

检索结果为空时，扩大候选范围重试一次：

```python
def retrieve(self, query, top_k=5):
    results = self.hybrid.retrieve(query, top_k * 2)
    if not results:
        results = self.hybrid.retrieve(query, top_k * 4)  # 降级重试
```

## 四、必做部分三：Prompt 工程与防幻觉控制

### 4.1 防幻觉四层机制

| 层级 | 机制 | 说明 |
|------|------|------|
| 检索层 | 相似度阈值过滤（final_score ≥ 0.3） | 低相关 chunk 不送入 LLM |
| 拦截层 | 无关问题检测（vector_score < 0.3） | 完全无关的问题直接短路返回，不调用 LLM |
| Prompt 层 | 9 条防幻觉规则 | 禁止捏造、引用标注、数字专项约束 |
| 后处理层 | 引用验证（`_fix_citations`） | 过滤超出 chunk 范围的引用序号 |

### 4.2 主问答 Prompt（9 条规则）

```
【回答规则】
1. 只能基于下方"参考文档"中的内容回答，禁止凭空捏造任何信息
2. 每一个关键事实必须用 [[序号]] 标注来源
3. 如果参考文档信息不完整，可合理推断但需注明"以下为基于文档片段的推断"
4. 涉及剂量、操作规程、安全警告等医疗敏感内容，必须原文引用，不得改写
5. 用中文回答，专业术语保持原文
6. 只有明显日常闲聊才拒答，技术类问题一律尽力作答
7. 参考文档中的 [章节名] 前缀是文档结构信息，不需要在回答中重复展示
8. 禁止编造任何数字、百分比、参数值、日期——必须原文引用，不得推断或估算
9. 每个句子最多标注 3 个引用来源，避免堆砌引用
```

规则 8 专门针对数字幻觉，是医疗场景最危险的错误类型。

### 4.3 无关问题拦截

pipeline 层用 `vector_score` 判断（不用 `final_score`，因为 BM25 为空时 final_score 偏低）：

```python
top_vector_score = retrieved_chunks[0].vector_score if retrieved_chunks else 0
if not filtered_chunks and top_vector_score < off_topic_threshold:
    return RAGResponse(answer="抱歉，您的问题超出了我的知识范围...", sources=[], ...)
```

### 4.4 引用溯源实现

每个 chunk 携带文件名、章节名、页码，来源显示格式：

```
[[1]] python-doc-27-34.pdf | 7. 复合语句 · 第224页 | 相关度 0.878
```

父子分块时，引用溯源来自子块 metadata（相关度是子块的向量相似度），但 LLM 看到的是父块内容（上下文更完整）。

### 4.5 多轮对话查询改写

多轮对话中含指代词的问题在检索前改写为完整问题，只有含指代词时才触发 LLM 改写：

```python
pronouns = ['它', '这个', '该', '上述', '前面', '之前', '其', '这些', '那个']
if not any(p in question for p in pronouns):
    return question  # 无指代词，直接返回
```

## 五、必做部分四：长上下文优化策略

### 5.1 分层 Token 预算分配

```
总预算：7000 tokens（8K窗口留1K余量）
├── 系统提示：500 tokens（固定，永远保留）
├── 对话历史：1000 tokens（压缩后）
├── 检索文档：4000 tokens（按相关性截断）
├── 用户问题：200 tokens
└── 回答空间：动态计算 = max(300, 7000 - 实际输入token)
```

**信息保留优先级**（从高到低）：系统提示 → 用户当前问题 → 最近 2 轮完整对话 → 早期历史摘要 → 高相关 chunk → 低相关 chunk（丢弃）

### 5.2 对话历史增量压缩

最近 2 轮完整保留，更早的轮次 LLM 增量压缩成摘要（不超过150字）。只压缩上次摘要之后新增的旧轮次，避免重复压缩：

```python
new_older = older[self._last_compressed_count:]  # 只处理新增的旧轮次
compress_prompt = f"已有摘要：{self.summary}\n新增对话：{new_history_text}\n更新后的摘要："
self._last_compressed_count = len(older)
```

### 5.3 检索文档 Token 控制

tiktoken 精确计数（降级兼容字符估算），超出预算时整体跳过 chunk（不截断，保证语义完整）：

```python
chunk_tokens = self._count_tokens(formatted)
if used_tokens + chunk_tokens > budget_tokens:
    break  # 整体跳过，不截断
```

### 5.4 动态生成预算

$$\text{max\_tokens} = \min\left(\text{configured\_max},\ \max(300,\ W - T_{\text{input}})\right)$$

确保输入 + 输出不超过模型上下文窗口。

### 5.5 Prompt 超限兜底

Prompt 超限时丢弃历史，只保留 context + question：

```python
if prompt_tokens > self.max_total_tokens:
    prompt = fallback_template.format(context=context, question=question)
```

## 六、选做方向 B：垂直领域 Embedding 微调

### 6.1 问题

开源 BGE 模型在通用语料上训练，对内部专有名词（型号、药品编号、诊断编码）向量表征差，导致检索精度低。

### 6.2 方案：LLM 合成问答对 + MultipleNegativesRankingLoss

参考 MIRACLE 论文（Arzideh et al., JMIR 2026）：

```
内部文档 → 切分（450字符/80重叠）→ LLM 生成 5 个问答对/chunk
         → 自动过滤（格式校验 + 幻觉检测）→ (问题, chunk) 训练对
         → MultipleNegativesRankingLoss 微调 BGE
         → 替换 settings.yaml 中的模型路径
```

**损失函数**：

$$\mathcal{L} = -\frac{1}{N}\sum_{i=1}^{N} \log \frac{e^{\text{sim}(q_i, d_i^+)/\tau}}{\sum_{j=1}^{N} e^{\text{sim}(q_i, d_j)/\tau}}$$

batch 内其他样本自动作为负样本，无需显式构造。

**CLI 命令**：

```bash
python main.py generate-finetune-data --source data/raw/ --output data/finetune/qa_pairs.jsonl
python main.py finetune --data data/finetune/qa_pairs.jsonl --output models/medical-bge-finetuned
```

**预期收益**（参考论文）：mAP@100 从 0.14 提升至 0.27，提升约 93%。
