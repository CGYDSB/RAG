# 垂直领域复杂文档 RAG 系统技术方案

**项目**：医疗领域内部技术文档智能问答系统
**技术栈**：Python / FastAPI / ChromaDB / BGE / DeepSeek / jieba

---

## 一、系统架构概览

```
用户问题
   ↓
[多轮消歧] 含指代词时 LLM 改写为完整问题
   ↓
Embedding（bge-small-zh-v1.5）→ 查询向量化
   ↓
混合检索
  ├─ 向量检索（ChromaDB 余弦相似度）→ Top-10 候选
  └─ 关键词检索（jieba 分词 + TF-IDF 倒排索引）→ Top-10 候选
         ↓
    加权融合（0.7 × vector_score + 0.3 × keyword_score）
   ↓
相似度阈值过滤（final_score ≥ 0.3）
   ↓
无关问题检测（vector_score < 0.3 → 直接拒答，不调用 LLM）
   ↓
Token 预算控制 → 构造上下文（tiktoken 精确计数，整体跳过低相关 chunk）
   ↓
对话历史压缩注入（最近 2 轮完整保留，更早轮次 LLM 增量压缩成摘要）
   ↓
Prompt 构造（防幻觉 9 条规则 + 章节归属前缀）
   ↓
LLM 生成（DeepSeek）→ 带 [[序号]] 引用的回答
   ↓
引用验证（过滤超出范围的引用序号）
   ↓
返回答案 + 来源文件 + 章节 + 页码
```

## 二、必做部分一：文档解析与分块

### 2.1 文本提取策略

支持 PDF / TXT / MD / DOCX / HTML 五种格式，核心在 PDF 处理上做了专项优化。

**PDF 文本清洗流程**（针对中文 PDF 提取乱码问题）：

```python
def _clean_pdf_text(self, text: str) -> str:
    # 1. 单个换行（断词）→ 空格，保留双换行（段落）
    text = re.sub(r'(?<!\n)\n(?!\n)', ' ', text)
    # 2. 去除多余空格和制表符
    text = re.sub(r'[ \t]+', ' ', text)
    # 3. 关键：去除中文字符之间的空格（PDF提取常见问题）
    text = re.sub(r'(?<=[\u4e00-\u9fff])\s+(?=[\u4e00-\u9fff])', '', text)
    # 4. 去除中文和标点之间的空格
    text = re.sub(r'(?<=[\u4e00-\u9fff])\s+(?=[，。！？、；：""''（）【】])', '', text)
    return text.strip()
```

每页文本插入 `[PAGE:N]` 标记，切分后 chunk 可反查原始页码，实现精准溯源。

**策略一：标题层级感知切片**

提取 PDF 书签目录（Outline），建立 0-based 页码 → 章节标题映射表，每个 chunk 携带 `section_path` 字段：

```python

    ...

def _build_page_to_section(self, entries, total_pages) -> Dict[int, str]:
    # 按页码区间建立映射：第5-11页 → "第3章 安装与配置"
    ...
```

无书签的 PDF 降级处理：`section_path` 为空字符串，行为与改动前一致。

**策略五：目录页过滤**

扫描前 20% 页面，识别含"目录/Contents"关键词的页面及其后续目录条目页，索引时跳过，避免目录条目与正文内容混淆干扰检索：

```python

    # 识别目录页首行关键词，连续过滤后续目录条目页（最多10页）
    ...
```

### 2.2 分块策略

采用**递归字符切分**（RecursiveCharacterSplitter），按语义边界优先级切分：

```
段落（\n\n）→ 行（\n）→ 句子（. ）→ 单词（空格）→ 字符
```

关键参数配置：

| 参数 | 值 | 说明 |
|------|-----|------|
| chunk_size | 256 | 较小粒度，语义更聚焦 |
| chunk_overlap | 30 | 重叠保留上下文连贯性（策略三） |
| min_chunk_size | 50 | 碎片块合并阈值（策略二） |

**策略二：碎片块合并**

切分后对长度小于 `min_chunk_size=50` 的碎片块合并到前一块，避免孤立标题行、单行数字等无意义片段进入向量库：

```python
def _merge_small_chunks(self, chunks) -> List[TextChunk]:
    merged = [chunks[0]]
    for chunk in chunks[1:]:
        if len(chunk.content) < self.min_chunk_size and merged:
            # 合并到上一块
            prev = merged[-1]
            merged[-1] = TextChunk(content=prev.content + "\n" + chunk.content, ...)
        else:
            merged.append(chunk)
    return merged
```

**ChromaDB 兼容性处理**：`base_metadata` 过滤掉嵌套 dict（`_page_to_section`），只保留 `str/int/float/bool` 类型，避免 ChromaDB 入库报错。

## 三、必做部分二：基础召回架构（混合检索）

### 3.1 整体流程

```
Query
  ├─→ Embedding（bge-small-zh-v1.5）→ 向量检索（ChromaDB）→ Top-10 候选
  └─→ jieba 分词 + TF-IDF 倒排索引 → Top-10 候选
         ↓
    归一化后加权融合（0.7 × vector + 0.3 × keyword）
         ↓
    相似度阈值过滤（final_score ≥ 0.3）
         ↓
    无关问题检测（vector_score < 0.3 → 直接拒答）
         ↓
    Top-5 最终结果
```

### 3.2 向量检索

使用 `BAAI/bge-small-zh-v1.5` 作为 Embedding 模型，专为中文语义理解优化。

bge 模型的特殊处理：query 检索时加前缀提升召回精度：

```python
# 检索时加前缀（文档索引时不加）
self._query_prefix = "为这个句子生成表示以用于检索相关文章："
```

### 3.3 关键词检索（jieba + TF-IDF）

引入 jieba 分词，解决原有空格切分对中文无效的问题：

```python
def _tokenize(self, text: str) -> List[str]:
    import jieba.posseg as pseg
    tokens = []
    for word, flag in pseg.cut(text):
        if word in self._CN_STOPWORDS or len(word) < 2:
            continue
        tokens.append(word)
        # 名词（n开头）权重翻倍：重复加入一次
        if flag.startswith('n') and len(word) >= 2:
            tokens.append(word)
    return tokens
```

**词权重差异化**：名词（`flag.startswith('n')`）在索引时重复加入，TF 翻倍，IDF 加权后权重约为普通词的 2 倍，保证专有名词、型号等精确词优先命中。

**关键词索引持久化**：索引完成后自动构建并持久化到 `data/keyword_index.pkl`，启动时自动加载，无需重新索引：

```python
# index_documents() 末尾
self.retriever.hybrid.build_keyword_index(keyword_docs)
self.retriever.hybrid.save_index()  # 持久化到磁盘
```

### 3.4 融合策略

两路结果各自归一化后加权融合：

```python
final_score = 0.7 × (vector_score / v_max) + 0.3 × (keyword_score / k_max)
```

**权重设计逻辑**：
- 向量检索权重更高（0.7），语义理解是主要需求
- 关键词权重（0.3）保证专有名词、型号等精确词不被遗漏
- 两路都命中的 chunk 得分叠加，天然实现"语义+精确"双重过滤

### 3.5 空结果降级

检索结果为空时，扩大候选范围重试一次：

```python
def retrieve(self, query, top_k=5):
    results = self.hybrid.retrieve(query, top_k * 2)
    if not results:
        results = self.hybrid.retrieve(query, top_k * 4)  # 降级重试
    ...
```

## 四、必做部分三：Prompt 工程与防幻觉控制

### 4.1 防幻觉四层机制

| 层级 | 机制 | 说明 |
|------|------|------|
| 检索层 | 相似度阈值过滤（final_score ≥ 0.3） | 低相关 chunk 不送入 LLM |
| 拦截层 | 无关问题检测（vector_score < 0.3） | 完全无关的问题直接短路返回，不调用 LLM |
| Prompt 层 | 9 条防幻觉规则 | 禁止捏造、引用标注、数字专项约束 |
| 后处理层 | 引用验证（`_fix_citations`） | 过滤超出 chunk 范围的引用序号 |

### 4.2 主问答 Prompt（9 条规则）

```
【回答规则】
1. 只能基于下方"参考文档"中的内容回答，禁止凭空捏造任何信息
2. 每一个关键事实必须用 [[序号]] 标注来源
3. 如果参考文档信息不完整，可合理推断但需注明"以下为基于文档片段的推断"
4. 涉及剂量、操作规程、安全警告等医疗敏感内容，必须原文引用，不得改写
5. 用中文回答，专业术语保持原文
6. 只有明显日常闲聊才拒答，技术类问题一律尽力作答
7. 参考文档中的 [章节名] 前缀是文档结构信息，不需要在回答中重复展示
8. 禁止编造任何数字、百分比、参数值、日期——必须原文引用，不得推断或估算
9. 每个句子最多标注 3 个引用来源，避免堆砌引用
```

规则 8 专门针对数字幻觉（编造参数值、统计数据），是医疗场景最危险的错误类型。

### 4.3 无关问题拦截

pipeline 层用 `vector_score` 判断（不用 `final_score`，因为 BM25 为空时 final_score 偏低）：

```python
top_vector_score = retrieved_chunks[0].vector_score if retrieved_chunks else 0
if not filtered_chunks and top_vector_score < off_topic_threshold:
    return RAGResponse(answer="抱歉，您的问题超出了我的知识范围...", sources=[], ...)
```

### 4.4 引用验证（后处理）

LLM 可能生成超出范围的引用序号（如只有 5 个 chunk 但生成了 `[[6]]`）。后处理过滤：

```python
@staticmethod
def _fix_citations(text: str, max_idx: int) -> str:
    def replace(m):
        idx = int(m.group(1))
        return m.group(0) if 1 <= idx <= max_idx else ''
    return re.sub(r'\[\[(\d+)\]\]', replace, text)
```

### 4.5 引用溯源实现

每个 chunk 携带文件名、章节名、页码，来源显示格式：

```
[[1]] python-doc-27-34.pdf | 7. 复合语句 · 第224页 | 相关度 0.878
```

chunk 格式化时前置文件名和章节名，帮助 LLM 感知内容来源：

```python
header = ' | '.join(filter(None, [filename, section_path]))
if header:
    text = f"[{header}]\n{text}"
```

### 4.6 多轮对话查询改写

多轮对话中含指代词的问题（"它的参数是多少？"）在检索前改写为完整问题：

```python
def _rewrite_question(self, question: str) -> str:
    pronouns = ['它', '这个', '该', '上述', '前面', '之前', '其', '这些', '那个']
    if not any(p in question for p in pronouns):
        return question  # 无指代词，直接返回
    # 用最近几轮对话作为上下文，LLM 改写
    ...
```

只有含指代词时才触发 LLM 改写，避免无谓的 API 消耗。

### 4.7 Prompt 模板体系

| 模板 | 场景 |
|------|------|
| `system.rag_assistant` | 默认问答，9 条防幻觉规则 |
| `system.conversational` | 多轮对话，携带历史摘要，8 条规则 |
| `system.concise` | 快速返回，简短回答 |

## 五、必做部分四：长上下文优化策略

### 5.1 问题背景

8K token 窗口需要容纳：系统提示 + 对话历史 + 检索文档 + 用户问题 + 回答空间，总量可能超过 20K。

### 5.2 分层 Token 预算分配

```
总预算：7000 tokens（8K窗口留1K余量）
├── 系统提示：500 tokens（固定，永远保留）
├── 对话历史：1000 tokens（压缩后）
├── 检索文档：4000 tokens（按相关性截断）
├── 用户问题：200 tokens
└── 回答空间：1500 tokens（动态计算，确保不超窗口）
```

**信息保留优先级**（从高到低）：
1. 系统提示（角色定义 + 约束规则）
2. 最近 2 轮完整对话（保持对话连贯性）
3. 早期历史摘要（保留关键约束和实体）
4. 当前轮检索文档（按相关性分数排序，整体跳过低相关 chunk）
5. 用户当前问题

### 5.3 对话历史增量压缩

```
对话历史（N轮）
    ├── 最近 2 轮：完整保留
    └── 更早的轮次：LLM 增量压缩成摘要（不超过150字）
              ↓
         只压缩上次摘要之后新增的旧轮次（增量压缩）
         压缩失败时 fallback：截断拼接
```

增量压缩避免重复压缩已处理的历史，节省 token 消耗：

```python
def compress_history(self, generator, gen_config) -> str:
    new_older = older[self._last_compressed_count:]  # 只处理新增的旧轮次
    if self.summary:
        compress_prompt = f"已有摘要：{self.summary}\n新增对话：{new_history_text}\n更新后的摘要："
    ...
    self._last_compressed_count = len(older)  # 记录已压缩到第几轮
```

### 5.4 检索文档 Token 控制

**精确 Token 计数**：引入 tiktoken，降级兼容字符估算：

```python
@staticmethod
def _count_tokens(text: str) -> int:
    try:
        import tiktoken
        enc = tiktoken.get_encoding("cl100k_base")
        return len(enc.encode(text))
    except ImportError:
        return len(text) // 2  # 中英混合降级估算
```

**不截断单个 chunk**：超出预算时整体跳过，保证每个进入 Prompt 的 chunk 语义完整：

```python
chunk_tokens = self._count_tokens(formatted)
if used_tokens + chunk_tokens > budget_tokens:
    break  # 整体跳过，不截断
context_parts.append(formatted)
used_tokens += chunk_tokens
```

### 5.5 动态生成预算

生成的 `max_tokens` 动态计算，确保输入 + 输出不超过模型上下文窗口：

```python
input_tokens = self._count_tokens(prompt)
available_for_output = max(300, self.max_total_tokens - input_tokens)
config = GenerationConfig(
    max_tokens=min(configured_max, available_for_output)
)
```

### 5.6 Prompt 超限兜底

最后一道防线：Prompt 超限时丢弃历史，只保留 context + question：

```python
prompt_tokens = self._count_tokens(prompt)
if prompt_tokens > self.max_total_tokens:
    logger.warning(f"Prompt too long ({prompt_tokens} tokens), dropping history")
    prompt = fallback_template.format(context=context, question=question)
```

| 组件 | 选型 | 理由 |
|------|------|------|

| 部署 | Docker Compose | 一键部署 |
