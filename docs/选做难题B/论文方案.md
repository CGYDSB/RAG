# 选做方向 B：垂直领域语义偏移与模型微调方案

**参考论文**：Arzideh et al., "Improving Retrieval Augmented Generation for Health Care by Fine-Tuning Clinical Embedding Models", JMIR 2026

---

## 一、问题分析

### 痛点

开源 Embedding 模型（如 BGE、multilingual-e5-large）在通用语料上表现良好，但在医疗内部文档中存在两类语义偏移问题：

1. **专有名词表征差**：内部设备型号（如"XYZ-990a 模块"）、药品编号（如"盐酸二甲双胍片 0.5g"）、诊断编码（如"ICD-10 E11.9"）在通用语料中出现极少，模型对这些词的向量表示接近随机，无法捕捉语义关系

2. **领域语义漂移**：通用模型对"心搏停止"和"心脏骤停"可能不认为是同义词；对"Hb"（血红蛋白缩写）和"血红蛋白"的向量距离可能很远

**核心原因**：<cite index="1-4,1-5">这些模型缺乏真实临床文档的训练，导致在医疗 RAG 系统中检索上下文不准确。这一差距在包含领域专有术语、缩写和细微临床语言的专科医疗文档中尤为突出。</cite>

---

## 二、整体方案

参考论文的 MIRACLE 方法，结合当前项目实际情况，设计以下微调方案：

```
内部文档库（PDF/DOCX）
         ↓
文档切分（450字符，80字符重叠）
         ↓
LLM 合成问答对生成（每个 chunk 生成 5 个问答对）
         ↓
数据过滤（去除幻觉、格式不合规的问答对）
         ↓
（可选）数据脱敏
         ↓
微调 Embedding 模型
（MultipleNegativesRankingLoss）
         ↓
评估（IR 指标 + RAG 指标）
         ↓
替换当前项目的 bge-small-zh-v1.5
```

## 三、训练数据构造

### 3.1 文档切分

<cite index="1-66,1-67,1-70,1-71">使用递归文本切分，最大 450 字符，重叠 80 字符。选择此重叠是为了确保文本段边界处的语义连续性，防止在切分点丢失临床上下文。切分器按以下优先级在自然断点处切分：段落（\n\n）、换行（\n）、词边界（空格），最后是单个字符，确保尽可能保留完整句子和段落。</cite>

对应当前项目的配置调整：

```yaml
# config/settings.yaml
document:
  default_chunk_size: 450    # 与论文对齐，比当前 256 更大
  default_chunk_overlap: 80  # 与论文对齐，比当前 30 更大
```

### 3.2 合成问答对生成

<cite index="1-73,1-74">对每个 chunk，使用 LLM 生成 5 个医学相关问题及文档 chunk 中包含的正确答案，以模拟真实临床问答场景。</cite>

**Prompt 设计**：

```
你是一个医疗文档分析专家。请基于以下文档片段，生成5个医学相关问题及对应答案。

要求：
1. 每个问题必须以问号结尾
2. 答案必须能从文档片段中直接找到依据
3. 问题应覆盖文档中的关键医疗信息（诊断、治疗、参数、操作规程等）
4. 避免询问行政信息（患者姓名、日期等）

文档片段：
{chunk}

请按以下格式输出：
1. 问题：...
   答案：...
2. 问题：...
   答案：...
```

**数据过滤规则**（参考论文）：

<cite index="1-79,1-80">为减少 LLM 产生的幻觉并提升数据质量，问答对通过定义标准进行系统过滤：所有问题必须以问号结尾，并以 1 到 5 之间的数字开头，确保每个 chunk 恰好生成 5 个问题。</cite>

过滤条件：
- 问题必须以问号结尾
- 答案不能为空
- 答案中的关键词必须能在原始 chunk 中找到（防止幻觉）
- 过滤纯行政类问题（含"姓名"、"日期"、"编号"等关键词的问题）

<cite index="1-210,1-211,1-212">论文的人工审计显示 18% 包含幻觉，6% 包含事实错误，76% 被验证为语义准确且临床正确。</cite>预期过滤后保留约 70-80% 的问答对。

### 3.3 数据规模估算

以当前项目知识库为例（6 个 PDF，约 1500 个 chunk）：

```
1500 chunks × 5 问答对/chunk = 7500 问答对
过滤后保留约 75% = ~5600 有效问答对
训练集/测试集 = 80%/20% = 4480 / 1120
```

对于医疗内部文档库（假设 10 万份文档）：

```
100,000 文档 → ~300,000 chunks（按论文比例）
300,000 × 5 = 1,500,000 问答对
过滤后 ~1,100,000 有效问答对
```

## 四、损失函数选择

### 4.1 MultipleNegativesRankingLoss（推荐）

<cite index="1-107">论文使用 sentence transformer 库的 CachedMultipleNegativesRankingLoss，minibatch 大小 32。</cite>

**原理**：

对于一个 batch 中的 N 个 (query, positive_doc) 对，每个 query 的负样本是 batch 中其他所有 positive_doc。损失函数最大化正样本对的相似度，同时最小化与负样本的相似度：

$$\mathcal{L} = -\frac{1}{N}\sum_{i=1}^{N} \log \frac{e^{\text{sim}(q_i, d_i^+)/\tau}}{\sum_{j=1}^{N} e^{\text{sim}(q_i, d_j)/\tau}}$$

其中 $\tau$ 为温度参数，$d_j$ 包含正样本 $d_i^+$ 和其他 $N-1$ 个负样本。

**为什么选这个损失函数**：
- 不需要显式构造负样本，batch 内其他样本自动作为负样本，数据构造成本低
- batch 越大，负样本越多，训练效果越好（论文 batch size=1024）
- 适合 (query, document) 对的检索任务

**代码示例**：

```python
from sentence_transformers import SentenceTransformer, InputExample
from sentence_transformers.losses import MultipleNegativesRankingLoss
from torch.utils.data import DataLoader

# 加载基础模型
model = SentenceTransformer("BAAI/bge-small-zh-v1.5")

# 构造训练数据：(问题, 文档chunk) 对
train_examples = [
    InputExample(texts=[question, chunk])
    for question, chunk in qa_pairs
]

train_dataloader = DataLoader(train_examples, shuffle=True, batch_size=64)
train_loss = MultipleNegativesRankingLoss(model)

# 训练
model.fit(
    train_objectives=[(train_dataloader, train_loss)],
    epochs=1,
    warmup_steps=100,
    output_path="models/medical-bge-finetuned"
)
```

### 4.2 备选：TripletLoss

如果有人工标注的负样本（明确不相关的文档），可以使用 TripletLoss：

$$\mathcal{L} = \max(0,\ \text{sim}(q, d^-) - \text{sim}(q, d^+) + \text{margin})$$

**适用场景**：有专家标注的"相关/不相关"文档对，精度更高但数据构造成本大。

### 4.3 备选：CoSENTLoss

对于有相关性分级（0/1/2分）的数据，CoSENTLoss 能利用分级信息：

$$\mathcal{L} = \log\left(1 + \sum_{(i,j): y_i > y_j} e^{\lambda(\text{sim}(q, d_j) - \text{sim}(q, d_i))}\right)$$

**适用场景**：有人工评分的检索数据集。

## 六、评估方案

### 6.1 IR 评估

<cite index="1-138,1-139,1-140">检索结果质量可通过 Accuracy@K、Precision@K 和 Recall@K 等指标衡量。对于 IR 系统，问题可定义为涉及搜索查询和多个结果的双重任务，使用截止阈值 K 计算评估指标可以确定结果质量。</cite>

评估指标：
- `mAP@100`：平均精度均值（论文主要指标）
- `NDCG@10`：归一化折扣累积增益
- `Recall@10`：召回率

### 6.2 RAG 评估

<cite index="1-160,1-161">使用 ROUGE 或 BLEURT 比较 LLM 输出与真实答案。此外计算上下文精度、上下文召回率和上下文相关性。</cite>

评估指标：
- `BERTScore-F1`：语义相似度
- `BLEURT`：语言质量
- `Contextual Precision/Recall`：检索上下文质量

## 八、预期收益与风险

**预期收益**（参考论文数据）：

<cite index="1-213">IR 评估指标显示微调 Embedding 模型性能更强，mAP@100 从 0.14 提升至 0.27，提升约 93%。</cite>

对于医疗内部文档场景，预期：
- 专有名词检索精度显著提升（型号、药品名、诊断编码）
- 领域同义词召回率提升（"心搏停止"↔"心脏骤停"）
- 整体 RAG 回答质量提升

**主要风险**：

<cite index="1-329,1-330,1-331">文档来自单一机构，模型容易出现模板过拟合——来自单一机构的临床文档通常共享固定的结构模板，存在模型将相关性与机构特有格式关联而非纯语义内容的风险。因此，性能可能无法完全迁移到文档标准不同的机构，需要本地微调。</cite>

<cite index="1-387,1-388,1-389,1-390">LLM 容易产生幻觉，可能生成事实不正确或临床不适当的内容，这会将潜在噪声引入训练数据集，可能传播到微调的 Embedding 模型。分析显示约 24% 的生成问答对包含幻觉或事实不准确。这引入了安全隐患，因为这类噪声有可能传播到 embedding 空间，有效地教导模型错误的语义关联。</cite>

**缓解措施**：
- 数据过滤（自动 + 人工抽检）
- 训练限制为 1 epoch，防止过拟合
- 保留原始 bge-small-zh-v1.5 作为 fallback，A/B 测试后再切换
