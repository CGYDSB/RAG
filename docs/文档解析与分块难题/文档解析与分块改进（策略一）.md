# 文档解析与分块改进（策略一：标题层级感知切片）

---

## 一、改动前的文档解析与分块

### 1.1 PDF 加载（data_loader.py）

改动前，`_load_pdf()` 只做了两件事：提取每页文本、插入页码标记。

```python
def _load_pdf(self, path: Path):
    reader = PdfReader(str(path))
    pages = []

    for i, page in enumerate(reader.pages):
        text = page.extract_text() or ""
        if text.strip():
            text = self._clean_pdf_text(text)
            pages.append(f"[PAGE:{i+1}] {text}")  # 只有页码标记

    content = "\n\n".join(pages)
    metadata = {"page_count": len(reader.pages), "type": "pdf"}  # 无结构信息
    return content, metadata
```

PDF 的书签目录（Outline）完全没有被读取，文档的章节结构信息在加载阶段就已经丢失。

### 1.2 文档切分（document_splitter.py）

改动前，`RecursiveCharacterSplitter.split()` 在构建每个 chunk 的 metadata 时，只记录了页码，没有任何标题归属信息：

```python
metadata = {
    **document.metadata,
    "chunk_index": i,
    "total_chunks": len(raw_chunks),
    "chunk_size": len(clean_content),
    "parent_doc_id": document.doc_id,
    "page": current_page,   # 只有页码，没有 section_path
}
```

切出来的 chunk 是孤立的正文片段，检索命中后无法知道它属于哪个章节。

### 1.3 上下文构建（rag_pipeline.py）

改动前，`_build_context_with_budget()` 直接把 chunk 文本拼入上下文，没有任何章节归属信息：

```python
for i, chunk in enumerate(chunks):
    citation = f"[[{i+1}]]"
    text = chunk.text
    # 直接使用原始文本，无章节前缀
    formatted = f"{citation} {text}"
```

LLM 看到的上下文是这样的：

```
[[1]] 安装前请确认系统版本不低于 3.8，使用 pip install 命令安装依赖...
[[2]] 配置文件位于 config/ 目录下，支持 YAML 格式...
```

没有章节信息，LLM 无法判断这两段内容是否属于同一章节，引用溯源也只能精确到页码。

## 二、改动详细说明

### 2.1 data_loader.py — 新增 Outline 提取与页码映射

#### 改动点一：`_load_pdf()` 新增书签提取逻辑

```python
# 提取 PDF 书签目录，建立页码 → 标题路径映射表
outlines = self._extract_outline(reader)
page_to_section = self._build_page_to_section(outlines, len(reader.pages))
if outlines:
    logger.info(f"Extracted {len(outlines)} outline entries from {path.name}")
else:
    logger.debug(f"No outline found in {path.name}, section_path will be empty")

metadata = {
    "page_count": len(reader.pages),
    "type": "pdf",
    "page_to_section": page_to_section,   # 新增：页码映射表
}
```

`page_to_section` 是一个 `Dict[int, str]`，key 是 0-based 页码，value 是该页所属的书签标题。这张映射表随 `Document.metadata` 传递给切分器。

#### 改动点二：新增 `_extract_outline()` 方法

```python
def _extract_outline(self, reader) -> List[Dict]:
    """
    提取 PDF 书签树，返回按页码排序的标题列表
    每项：{'title': str, 'page': int, 'level': int}
    """
    outlines = []

    def _walk(items, level=1):
        for item in items:
            if isinstance(item, list):
                _walk(item, level + 1)   # 递归处理嵌套书签
            else:
                try:
                    page_num = reader.get_destination_page_number(item)
                    title = item.title.strip() if item.title else ""
                    if title:
                        outlines.append({
                            'title': title,
                            'page': page_num,
                            'level': level,
                        })
                except Exception:
                    pass   # 单个书签解析失败不影响整体

    try:
        _walk(reader.outline)
    except Exception as e:
        logger.debug(f"Outline extraction failed: {e}")

    return sorted(outlines, key=lambda x: x['page'])
```

`reader.outline` 是 pypdf 提供的书签树，结构是嵌套列表，子列表代表下一级书签。`_walk()` 递归遍历，`level` 参数记录层级深度（当前实现存储了 level 字段，为后续扩展完整祖先路径预留）。整个过程有完整的异常保护，单个书签解析失败不会中断整体流程。

#### 改动点三：新增 `_build_page_to_section()` 方法

```python
def _build_page_to_section(self, outlines: List[Dict], total_pages: int) -> Dict[int, str]:
    """
    按页码区间建立 page → section_path 映射。
    chunk 的页码落在哪两个相邻书签之间，就归属于前一个书签节点。
    """
    if not outlines:
        return {}

    mapping = {}
    for i, outline in enumerate(outlines):
        end_page = outlines[i + 1]['page'] if i + 1 < len(outlines) else total_pages
        for page in range(outline['page'], end_page):
            mapping[page] = outline['title']

    return mapping
```

映射逻辑：书签 A 在第 5 页，书签 B 在第 12 页，则第 5-11 页的所有内容都归属于书签 A。最后一个书签到文档末尾的所有页面同理处理。

### 2.2 document_splitter.py — 切分时注入 section_path

`RecursiveCharacterSplitter.split()` 新增两处改动：

#### 改动点一：从 document metadata 取出映射表

```python
# 从 document metadata 取出页码 → 标题路径映射表（PDF 有，其他格式为空）
page_to_section = document.metadata.get('page_to_section', {})
```

非 PDF 格式（TXT、DOCX 等）的 `document.metadata` 里没有 `page_to_section`，`get()` 返回空 dict，后续逻辑自然降级，`section_path` 为空字符串，行为与改动前完全一致。

#### 改动点二：查表写入 section_path，并清理映射表

```python
# 查找当前页对应的标题路径（页码从1开始，映射表用0-based页码）
section_path = page_to_section.get(current_page - 1, '')

metadata = {
    **document.metadata,
    "chunk_index": i,
    "total_chunks": len(raw_chunks),
    "chunk_size": len(clean_content),
    "parent_doc_id": document.doc_id,
    "page": current_page,
    "section_path": section_path,   # 新增
}
# page_to_section 不需要存入每个 chunk 的 metadata（太大），移除
metadata.pop('page_to_section', None)
```

两个细节：
- 页码转换：`[PAGE:N]` 标记是 1-based，映射表的 key 是 0-based（pypdf 的页码从 0 开始），所以查表时用 `current_page - 1`
- 内存优化：`page_to_section` 映射表可能有几百条记录，如果每个 chunk 的 metadata 都带一份，向量库存储开销会很大。通过 `metadata.pop()` 在写入 chunk 前移除，只保留当前 chunk 需要的 `section_path` 字符串

### 2.3 rag_pipeline.py — 上下文构建前置标题路径

#### 改动点一：`_build_context_with_budget()` 前置 section_path

```python
# 如果 chunk 有标题路径，前置显示，帮助 LLM 理解归属
section_path = chunk.metadata.get('section_path', '') if chunk.metadata else ''
if section_path:
    text = f"[{section_path}]\n{text}"
```

改动后 LLM 看到的上下文变为：

```
[[1]] [第3章 安装与配置]
安装前请确认系统版本不低于 3.8，使用 pip install 命令安装依赖...

[[2]] [第3章 安装与配置]
配置文件位于 config/ 目录下，支持 YAML 格式...
```

LLM 能明确知道这两段内容都属于"第3章 安装与配置"，生成答案时引用更准确，也不会把不同章节的内容混淆。

#### 改动点二：`_generate_response()` sources 返回值加入 section_path

```python
sources = [
    {
        "index": i + 1,
        "text": c.text[:200],
        "metadata": c.metadata,
        "score": c.final_score,
        "section_path": c.metadata.get('section_path', '') if c.metadata else '',  # 新增
    }
    for i, c in enumerate(chunks)
]
```

API 返回的 sources 里现在带有章节信息，前端或调用方可以展示更精准的引用来源，例如：

```
[1] Score: 0.85 | 第3章 安装与配置 | python-doc.pdf | 第10页
```

## 三、改动总结

### 涉及文件

| 文件 | 改动类型 | 新增代码量 |
|------|----------|-----------|
| `src/data_loader.py` | 新增 3 个方法 | ~55 行 |
| `src/document_splitter.py` | 修改 `split()` | ~8 行 |
| `src/rag_pipeline.py` | 修改 2 处 | ~6 行 |

### 数据流变化

```
改动前：
PDF → [PAGE:N] 文本 → chunk（只有页码）→ LLM 上下文（无章节信息）

改动后：
PDF → [PAGE:N] 文本
    + Outline 提取 → page_to_section 映射表
         ↓
    chunk（页码 + section_path）→ LLM 上下文（[章节名]\n正文）
                                  API sources（含 section_path）
```

### 兼容性

- 无 Outline 的 PDF：`_extract_outline()` 返回空列表，`page_to_section` 为空 dict，`section_path` 为空字符串，所有下游逻辑走 `if section_path:` 的 else 分支，行为与改动前完全一致
- 非 PDF 格式（TXT / DOCX / HTML）：`document.metadata` 里没有 `page_to_section`，`get()` 返回空 dict，同上
- 不需要重新安装任何依赖，`pypdf` 已在 `requirements.txt` 中

### 未实现部分（后续可扩展）

- 完整祖先路径拼接：当前只取命中书签的标题，不拼接父级标题（如"第3章 > 3.1节"）。`_extract_outline()` 已存储 `level` 字段，后续可在 `_build_page_to_section()` 中增加祖先路径构建逻辑
- 无 Outline 文档的正则兜底：对于没有书签的 PDF，可通过统计编号模式（`第X章`、`X.X`）自动识别标题，参考 RAGFlow 的 `title_frequency()` 实现
