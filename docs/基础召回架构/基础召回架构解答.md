# 基础召回架构解答

**面试题**：基础召回架构（Retrieval）

1. 设计一个混合检索（Hybrid Search）流程（如：向量检索 + 关键词检索）。
2. 请简述你如何整合这两路召回的结果，并给出逻辑说明。

---

## 问题一：混合检索流程设计

### 为什么需要混合检索

单路召回有天然缺陷：

- **纯向量检索**：擅长语义相似，但对精确术语不敏感。查询"胰岛素注射剂量"，向量检索可能召回语义相近但药品不同的文档
- **纯关键词检索（BM25）**：精确匹配强，但无法理解同义词和语义变体。查询"心脏骤停处理"无法召回描述"心搏停止急救流程"的文档

混合检索让两路互补：**向量检索兜底语义，关键词检索保证精确**。

---

### 整体流程

```
用户查询 "阿司匹林禁忌症"
         │
         ├─── 路一：向量检索
         │     ├─ bge-small-zh-v1.5 向量化查询（加前缀）
         │     ├─ ChromaDB 余弦相似度 KNN
         │     └─ 返回 Top-10 候选（含 vector_score）
         │
         └─── 路二：关键词检索
               ├─ jieba 分词：["阿司匹林", "阿司匹林", "禁忌症"]（名词重复）
               ├─ TF-IDF 倒排索引查询
               └─ 返回 Top-10 候选（含 keyword_score）
                        ↓
              归一化后加权融合
                        ↓
              相似度阈值过滤（final_score ≥ 0.3）
                        ↓
              Top-5 最终结果
```

---

### 路一：向量检索

**Embedding 模型**：`BAAI/bge-small-zh-v1.5`，专为中文语义理解优化，本地运行，dim=512。

**余弦相似度**：

$$\text{cosine\_sim}(q, d) = \frac{q \cdot d}{\|q\| \cdot \|d\|}$$

bge 模型检索时加前缀，提升召回精度（索引时不加）：

```python
self._query_prefix = "为这个句子生成表示以用于检索相关文章："
query_vec = model.encode(prefix + question)
```

**为什么加前缀**：bge 模型在训练时区分了"文档表示"和"查询表示"，加前缀告诉模型当前是检索场景，生成的向量更适合做相似度匹配。

---

### 路二：关键词检索（jieba + TF-IDF）

**分词**：引入 jieba 替代空格切分，解决中文无空格分隔的问题：

```python
def _tokenize(self, text: str) -> List[str]:
    import jieba.posseg as pseg
    tokens = []
    for word, flag in pseg.cut(text):
        if word in self._CN_STOPWORDS or len(word) < 2:
            continue
        tokens.append(word)
        # 名词（n开头）权重翻倍：重复加入一次
        if flag.startswith('n') and len(word) >= 2:
            tokens.append(word)
    return tokens
```

**词权重差异化**：名词在索引时重复加入，TF 翻倍，IDF 加权后权重约为普通词的 2 倍。"阿司匹林"（名词）比"禁忌"（形容词）权重更高，保证药品名称等专有名词优先命中。

**TF-IDF 评分**：

$$\text{score}(t, d) = \text{TF}(t, d) \times \text{IDF}(t), \quad \text{IDF}(t) = \ln\frac{N+1}{df(t)+1}$$

其中 $N$ 为文档总数，$df(t)$ 为包含词 $t$ 的文档数。稀有词（如药品编号、手术器械型号）IDF 值高，在评分中权重更大。

**索引持久化**：索引完成后 pickle 持久化到 `data/keyword_index.pkl`，启动时自动加载，无需重新索引：

```python
# 索引阶段
self.retriever.hybrid.build_keyword_index(keyword_docs)
self.retriever.hybrid.save_index()

# 启动时自动加载
def _load_index(self):
    if Path(self.index_path).exists():
        data = pickle.load(open(self.index_path, "rb"))
        self._keyword_index = data["index"]
        self._total_docs = data["total_docs"]
```

## 问题二：两路结果整合

### 整合策略：归一化加权融合

**核心公式**：

$$\text{final\_score} = \alpha \cdot \frac{s_v}{s_v^{\max}} + (1-\alpha) \cdot \frac{s_k}{s_k^{\max}}$$

其中 $\alpha = 0.7$（向量权重），$s_v$ 为向量相似度，$s_k$ 为 TF-IDF 分数。

**代码实现**：

```python
def _fuse(self, vector_results, keyword_results, top_k) -> List[RetrievedChunk]:
    chunks: Dict[str, RetrievedChunk] = {}

    # 各自归一化（除以本路最大值）
    v_max = max((r["score"] for r in vector_results), default=1.0) or 1.0
    k_max = max((r["score"] for r in keyword_results), default=1.0) or 1.0

    # 路一：向量检索结果入库
    for r in vector_results:
        chunks[r["id"]] = RetrievedChunk(
            id=r["id"], text=r.get("text", ""),
            metadata=r.get("metadata", {}),
            vector_score=r["score"] / v_max      # 归一化到 [0,1]
        )

    # 路二：关键词结果合并（已有的叠加，没有的新建）
    for r in keyword_results:
        if r["id"] in chunks:
            chunks[r["id"]].keyword_score = r["score"] / k_max   # 两路都命中
        else:
            chunks[r["id"]] = RetrievedChunk(
                id=r["id"], text=r.get("text", ""), metadata={},
                keyword_score=r["score"] / k_max                  # 仅关键词命中
            )

    # 加权融合
    for c in chunks.values():
        c.final_score = 0.7 * c.vector_score + 0.3 * c.keyword_score

    return sorted(chunks.values(), key=lambda x: x.final_score, reverse=True)[:top_k]
```

---

### 为什么这样设计：逻辑说明

**1. 为什么要归一化**

向量相似度（余弦）范围是 $[-1, 1]$，TF-IDF 分数没有固定上界（取决于词频和文档数），两者量纲完全不同。直接加权会导致 TF-IDF 分数压制向量分数（或反之）。归一化后两路都在 $[0, 1]$ 范围内，加权才有意义。

**2. 为什么向量权重更高（0.7）**

医疗技术文档的查询以语义理解为主——用户问"如何预防术后感染"，文档里可能写的是"手术切口护理与抗菌处理规范"，向量检索能捕捉这种语义等价，关键词检索则无法匹配。所以向量检索是主路，权重更高。

**3. 为什么关键词权重不能为 0**

医疗文档中大量专有名词、药品编号（如"盐酸二甲双胍片"、"ICD-10 E11.9"）在向量空间里表示很差——这些词在通用语料中出现极少，embedding 模型对它们的理解不准确。关键词检索通过精确匹配弥补这个盲区，0.3 的权重保证药品名称、诊断编码等精确词不被遗漏。

**4. 两路都命中的 chunk 天然得分更高**

如果一个 chunk 同时被向量检索和关键词检索命中，它的 `final_score = 0.7 × vector_score + 0.3 × keyword_score`，两路分数叠加，自然排在前面。这实现了"语义相关 + 精确匹配"的双重过滤，是混合检索最核心的优势。

**5. 仅一路命中的 chunk 如何处理**

- 仅向量命中：`keyword_score = 0`，`final_score = 0.7 × vector_score`，最高 0.7
- 仅关键词命中：`vector_score = 0`，`final_score = 0.3 × keyword_score`，最高 0.3

仅关键词命中的 chunk 最高分只有 0.3，恰好等于 `similarity_threshold`，会被阈值过滤掉。这是合理的——只有关键词匹配但语义不相关的 chunk，不应该进入 LLM 的上下文。

### 融合结果示例

查询"什么是函数"，融合后的来源分布：

```
[[1]] python-doc-27-34.pdf | 4. 控制流 · 第28页  | 相关度 0.878  ← 两路都命中
[[2]] python-doc-27-34.pdf | 7. 复合语句 · 第226页 | 相关度 0.780  ← 两路都命中
[[3]] python-doc-27-34.pdf | 7. 复合语句 · 第224页 | 相关度 0.700  ← 仅向量命中
[[4]] python-doc-27-34.pdf | 5. 表达式 · 第208页  | 相关度 0.698  ← 仅向量命中
[[5]] python-doc-27-34.pdf | 7. 复合语句 · 第225页 | 相关度 0.580  ← 仅向量命中
```

第28页（控制流章节，专门讲函数调用）因为"函数"这个词在该页 TF-IDF 权重高，关键词路给它加了分，从纯向量检索时的第5位跳到第1位。这正是混合检索的价值所在。

### Reranker 精排

混合检索后可选接 Cross-Encoder Reranker，对每个 (query, chunk) 对单独计算相关性：

$$\text{final\_score} = 0.3 \cdot s_{\text{hybrid}} + 0.7 \cdot \sigma(r)$$

其中 $\sigma(r) = \frac{1}{1+e^{-r}}$ 为 sigmoid 归一化，将 Cross-Encoder 原始 logit 映射到 $(0,1)$，与混合检索分数量纲对齐。

当前项目在 CPU 环境下默认关闭（避免额外模型下载和性能开销），可通过配置开启：

```yaml
reranker:
  enabled: true
  model: "cross-encoder/ms-marco-MiniLM-L-6-v2"
  top_n: 5
```

## 总结

| 维度 | 向量检索 | 关键词检索 | 混合检索 |
|------|----------|------------|----------|
| 擅长 | 语义相似、同义词 | 精确匹配、专有名词 | 两者兼顾 |
| 弱点 | 专有名词、型号 | 语义变体、近义词 | — |
| 权重 | 0.7 | 0.3 | — |
| 分词 | BGE embedding | jieba（名词权重×2） | — |
| 索引 | ChromaDB 向量库 | pickle 倒排索引 | — |
